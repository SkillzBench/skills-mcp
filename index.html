What it is

Skills MCP is a single Model Context Protocol server at mcp.skillzbench.com/mcp that serves the SkillzBench skill catalog. Instead of copy-pasting skill files into every project, you connect once and your agent can search, inspect, and load any skill you've enabled — with provenance, license class, and benchmark results attached.

Connect in under 5 minutes

# Claude Code
claude mcp add --transport http skillzbench https://mcp.skillzbench.com/mcp \
  --header "Authorization: Bearer sb_live_YOUR_KEY"
{
  "mcpServers": {
    "skillzbench": {
      "type": "http",
      "url": "https://mcp.skillzbench.com/mcp",
      "headers": { "Authorization": "Bearer sb_live_YOUR_KEY" }
    }
  }
}

get_skillLoad one SKILL.md — with provenance header
get_skill_infoSummary, benchmark Lift, scan verdict, license
request_enable / request_disableToggle skills — instantly on auto agents, one-click human approval otherwise

Why this one is different

  • Advertise many, load one. Your agent sees only name + description until it loads a skill — context stays small.
  • You stay in control. Agents can only load skills you enabled; enabling is ask-by-default with an approval link.
  • Every skill is vetted. Static scanning for secrets and exfiltration, license classification, two independent LLM judges, and human review before publish.
  • Benchmarked, not just listed. Skills carry a measured Lift score — did the skill actually make a reference agent better at category tasks?

Skills MCP FAQ

Is it free?

Yes — browsing, the directory, and the MCP with a personal loadout are free during launch.

Which clients work?

Any MCP client that supports Streamable HTTP with header auth: Claude Code, Cursor, Zed, and custom SDK clients. A zero-dependency CLI (skillzbench init) prints ready-to-paste config.

Can skills be dangerous?

All published skills pass a deterministic scanner (secrets, hooks, exfiltration URLs, tool breadth) plus two LLM judges; benchmark runs plant canary credentials and quarantine any skill that tries to leak them. See the methodology.
